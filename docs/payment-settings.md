# Оплата семестров RAUDA ILM

Владелец открывает «Оплата» в приложении или Telegram-админке. Укажите цену семестра, включите приём оплаты в школе и нужные способы: Tribute и/или ЮMoney. У каждого семестра отдельные переключатели. Новые глобальные способы изначально выключены. Настройки сохраняются только владельцем; API никогда не возвращает значения секретов.

Ссылка закрытого Telegram-канала задаётся у семестра. После подтверждённой оплаты бот присылает эту ссылку и кнопку семестра. Приложение создаёт заказ от имени вошедшего ученика, поэтому перед оплатой нужно привязать Telegram и запустить бота.

## Tribute

1. Создайте отдельный **цифровой продукт** для каждого семестра в кабинете Tribute. Продукт другого семестра повторно использовать нельзя.
2. В настройках школы заполните числовой ID продукта, его ссылку, валюту и точную цену. Короткий код ссылки может отличаться от ID: например, ID `2548`, ссылка `https://t.me/tribute_bot/app?startapp=pf6` или `https://web.tribute.tg/p/f6`. Цена Tribute указывается в выбранной валюте; обычная цена семестра — в рублях.
3. Секрет Cloudflare `TRIBUTE_API_KEY` должен содержать API-ключ этого кабинета Tribute.
4. Адрес webhook в Tribute: `https://<рабочий-домен>/api/webhooks/tribute`.

Перед созданием заказа сервер читает продукт через API Tribute и проверяет ссылку, ID, сумму, валюту, тип и публикацию. Сервер проверяет HMAC-SHA256 заголовка `trbt-signature` по исходному телу запроса. Продукт связывается с ожидающим заказом по Telegram ID покупателя, ID продукта, валюте и сумме. Возврат связывается по `purchase_id`; повторы не создают второй доступ. Подписанный старый поток оплаты программы сохранён.

Официальные источники: [подключение цифровых продуктов](https://wiki.tribute.tg/for-content-creators/info-products-and-content/api-integration), [webhooks](https://wiki.tribute.tg/for-content-creators/api-documentation/webhooks).

## ЮMoney

1. Введите кошелёк получателя, начинающийся с `4100`. Если настройка ещё не сохранена, используется существующий `YOOMONEY_WALLET`.
2. В Cloudflare сохраните секрет HTTP-уведомлений как `YOOMONEY_NOTIFICATION_SECRET`. Также поддерживается `YOOMONEY_WEBHOOK_SECRET`; при наличии обоих используется первый.
3. В настройках HTTP-уведомлений ЮMoney задайте `https://<рабочий-домен>/api/webhooks/yoomoney`.
4. Включите ЮMoney в школе и у нужного семестра.

Ученику приходит ссылка на форму заказа. Форма отправляет POST на официальный адрес ЮMoney; доступны кошелёк и банковская карта. Уникальная метка `label` связывает перевод с заказом. Сервер сверяет подпись `sign`, валюту RUB, сумму списания `withdraw_amount`, метку и ID операции. Тестовые или незачисленные переводы доступа не дают.

С 18 мая 2026 года ЮMoney использует `sign` HMAC-SHA256 вместо устаревшего `sha1_hash`. При смене кошелька или секрета сначала разберите ожидающие заказы старого кошелька; старые ссылки после изменения кошелька предлагают создать новый заказ.

Официальные источники: [HTTP-уведомления и подпись](https://yoomoney.ru/docs/payment-buttons/using-api/notifications), [форма оплаты](https://yoomoney.ru/docs/payment-buttons/using-api/forms).

## Данные и проверки

Сохраняются существующие `courses`, `semesters`, `payments`, `user_semesters`, `semester_payment_methods`, `semester_payment_grants`. Дополняются поля привязки продукта в `semester_payment_methods`; отдельные `semester_payment_orders` и `semester_payment_events` хранят связь заказа, защиту от повтора и состояние доставки сообщений. SQL совместим с текущей D1 и старой схемой репозитория. Запись оплаты и выдача доступа выполняются одной транзакцией D1.

У новых платежей этого модуля `payments.amount` содержит точную сумму провайдера в **минимальных единицах валюты** (копейках/центах), `payments.currency` — реальную валюту платежа. Ранее существующие строки не изменяются. Для отображения и сверки используйте заказ: `amount_minor`, `currency`; рублёвая цена семестра отдельно фиксируется в `tuition_price_rub`. Это позволяет оплатить продукт Tribute в USD/EUR без ошибочной записи такой операции как RUB.

Доступ определяет `user_semesters.status='active'`. В текущей D1 срок остаётся `NULL`; старой схеме с обязательным сроком записывается техническое значение `9999-12-31`, которое не используется как основная модель доступа. Блокировку семестра оплата не снимает.

Возврат страницы оплаты или кнопка проверки статуса сами по себе никогда не подтверждают платёж. При сбое Telegram платёж остаётся сохранённым, а повтор webhook или проверка заказа повторяют недоставленное подтверждение. Финансовые настройки и реальные платежи автоматическими тестами не изменяются.

Проверка: `node --test backend/test/payments.test.mjs`.
