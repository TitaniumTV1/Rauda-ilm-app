# Обучение в приложении и Telegram

Учебные сущности сохраняют существующую иерархию базы: **курс → программа → семестр → предмет → урок**. Telegram и приложение используют одни `users.id`, записи доступа, прогресс и попытки. Новые таблицы миграции `008_learning.sql` добавляют состояния, не заменяют учебную или платёжную историю. Production в ходе разработки не изменяется.

## Доступ и прохождение

Ученик получает материалы только с действующим доступом к соответствующему разделу. Учитываются блокировка аккаунта, видимость урока/предмета/предков, статус и срок доступа. Членство в группе само по себе не заменяет оплату или выдачу доступа администратором. По умолчанию следующий урок открывается после предыдущих видимых уроков семестра. Завершение сохраняется через общий `saveProgress`; событие плеера не отменяет уже завершённый урок.

В Telegram доступны `/learn`, `/exams`, `/groups`, `/certificates`. Кнопка «Программа курса» ведёт в новый каталог. Урок показывает текст, переход к файлам/плееру приложения, завершение и следующий урок. Сложные административные редакторы открываются из `/admin_learning` в защищённой веб-админке. Доступ к этим действиям проверяется сервером, включая назначения `admin_courses`.

## Экзамены

Редактор принимает вопросы с одним или несколькими правильными вариантами: 1–100 вопросов, 2–8 различных непустых вариантов, положительные баллы. Вопросы с ручной проверкой текста не маскируются под автоматически проверяемые: API их отклоняет. Правильные варианты выдаются только администратору с правом `exams`.

Параметры экзамена: проходной процент, число попыток, 1–240 минут, окно доступности, все уроки раздела либо выбранные обязательные уроки, доступ по назначению ученику/группе. Назначение ограничивает доступ, но не создаёт оплату. Индивидуальное разрешение может открыть работу и добавить попытку даже успешно сдавшему.

Начало атомарно резервирует одну строку в существующей `exam_attempts` и записывает закрытый снимок вопросов/ключей в `school_exam_attempts`. Повторное начало возвращает текущую попытку; два параллельных запроса не расходуют две попытки. Изменение экзамена не меняет уже начатую работу. Сервер фиксирует дедлайн с учётом окна назначения. Просроченная отправка записывается как `timed_out` с нулевыми баллами; правильные ответы после дедлайна не принимаются. Повторная отправка возвращает уже записанный результат.

Черновики ответов хранятся на сервере в попытке и могут продолжаться в обоих интерфейсах. В Telegram выбор одного и того же варианта идемпотентен; старая кнопка другого вопроса не меняет текущий ответ. Серверный результат записывается в прежнюю `exam_attempts`, поэтому оценки остаются совместимы с существующими экранами.

`assessment_access` — единый источник дополнительных попыток. Старый маршрут `/api/admin/students/retake` перехватывает новый обработчик. Старые строки `assessment_retake_permissions`, если таблица существует, переносятся один раз с маркером; исходные записи сохраняются. Нельзя вновь запускать старый writer в обход нового маршрутизатора.

## Сертификаты

Условия выпуска: включённая выдача, доступ к курсу, завершение опубликованных уроков при включённом условии, успешные обязательные экзамены и проходной результат. Название, организация, цвет, подпись и условия задаются через настройки сертификата. Имя или кунью можно указать при выпуске, если это разрешено настройками.

Результат — **печатный HTML**, доступный авторизованному владельцу или разрешённому администратору. Браузер может сохранить его в PDF через печать. Это не нативная генерация PDF и не графический редактор макета. Telegram отправляет защищённую ссылку, для которой нужен вход в приложение. Повторный выпуск при наличии действующего сертификата возвращает тот же сертификат. После отзыва скачивание отвечает `410`. Ранее выпущенные HTML-документы могут быть сохранены пользователем; отзыв не удаляет такие локальные копии.

## HTTP-контракты

Все JSON-ответы содержат `ok`; ошибки — `error`. POST/PATCH принимают JSON. Ученические маршруты требуют активную сессию, административные — соответствующее право и назначенный курс.

| Маршрут | Назначение |
|---|---|
| GET `/api/learning/catalog` (также `/tree`) | Массивы `courses`, `programs`, `semesters`, `subjects` с `has_access`; без закрытого содержания уроков |
| GET `/api/admin/learning/catalog` | Те же сущности и `lessons`, ограниченные курсами администратора |
| POST/PATCH/DELETE `/api/admin/learning/{courses,programs,semesters,subjects,lessons}[/:id]` | Создание, изменение и безопасное скрытие учебного контента; ответ `item` |
| GET `/api/learning/lessons?semester_id=…&subject_id=…` | Список заголовков, прогресса, `locked`, `lock_reason` |
| GET `/api/learning/lessons/:id` | `lesson`, содержимое, файлы с защищёнными URL, прогресс |
| POST `/api/learning/lessons/:id/complete` | `progress`, `next_lesson_id` |
| GET `/api/learning/groups` | Собственные группы |
| GET/POST/PATCH/DELETE `/api/admin/learning/groups[/:id]` | Группа с `course_id`, необязательными `program_id`, `semester_id`, `cohort`; DELETE архивирует |
| GET/POST/DELETE `/api/admin/learning/groups/:id/members[/:userId]` | Участники и прогресс; POST `{user_id}` |
| GET `/api/learning/exams` | Экзамены с лимитами, `can_attempt`, `reason`, `active_attempt_id` |
| GET/POST/PATCH/DELETE `/api/admin/learning/exams[/:id]` | Экзамены с вложенными `questions[].answers[]`; ключи только в админке |
| GET/POST/DELETE `/api/admin/learning/exams/:id/assignments[/:assignmentId]` | POST `{target_type:'user'|'group',target_id,is_open,opens_at,closes_at}` |
| GET `/api/admin/learning/exams/:id/attempts` | Попытки и результаты учеников |
| POST `/api/learning/exams/:id/start` | `attempt:{id,exam_id,title,status,deadline_at,questions,answers}` без ключей |
| GET `/api/learning/attempts/:id` | Собственная попытка и результат |
| PATCH `/api/learning/attempts/:id/answers` | Черновик `{answers:{questionId:[answerIds]}}` |
| POST `/api/learning/attempts/:id/submit` | Та же форма ответов; возвращает `attempt,result:{score,max_score,percentage,passed,timed_out}` |
| POST `/api/admin/students/retake` | `{user_id,assessment_id,type,extra_attempts?,reason?}`; каноническая дополнительная попытка |
| GET/POST `/api/learning/certificates` | Собственные сертификаты; выпуск `{course_id,certificate_name}` |
| GET/POST `/api/admin/learning/certificates` | Просмотр/выпуск с дополнительным `user_id` и теми же условиями |
| GET `/api/learning/certificates/eligibility/:courseId` | `eligible`, `reason`, `settings` |
| GET `/api/learning/certificates/:id/download` | Авторизованный HTML-документ |
| POST `/api/admin/learning/certificates/:id/revoke` | Отзыв |
| GET/PATCH `/api/admin/learning/certificate-settings/:courseId` | Условия выдачи и оформление HTML-сертификата |

Существующий файловый API `/api/admin/lessons/:id/files` сохраняется. Все маршруты нового модуля необходимо подключать **до** legacy-маршрутов. Перед ними вызывается общая совместимая миграция `ensureSchoolSchema`; `ensureLearningSchema` вызывается модулем самостоятельно.

## Проверки

`node --test backend/test/learning.test.mjs` выполняет SQL на SQLite в памяти: доступ/истечение/скрытый контент, последовательность, предметные права и назначения курсов, проверку вопросов, сокрытие ключей, параллельный старт/отправку, снимок экзамена, дедлайн, пересдачу после успеха, назначения группе/ученику, общие черновики между интерфейсами, одноразовый перенос legacy-пересдач, сертификаты и Telegram-прохождение. Production D1, Telegram и платёжные провайдеры тестами не вызываются.
